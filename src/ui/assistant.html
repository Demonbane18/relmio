Required n8n prerequisite

The existing n8n service must have N8N_ENABLED_MODULES=instance-ai applied before Relmio can continue. If it is already configured without instance-ai, append instance-ai as a distinct comma-delimited token while preserving existing module entries; do not replace unknown existing values.

  1. Use your existing Hostinger/deployment workflow to update the n8n service.
  2. Redeploy or restart n8n, then verify that it is healthy.
  3. Reconnect to Relmio and run discovery again.
Why Relmio cannot apply this change

Relmio reports only this allowlisted status and never displays the raw environment value. It will not edit the existing n8n Compose file, image, or environment; restart or recreate n8n; or exec into n8n.

Relmio must verify instance-ai before a plan can be reviewed.

Platform account guardrails

No setup can guarantee an account is never flagged.

Use a dedicated OpenAI Platform project/key, store it server-side in n8n, set project rate/spend limits and alerts, monitor usage, grant least user access, rotate or revoke credentials as needed, require human review, and never expose this provider path publicly.

Relmio cannot inject per-user safety identifiers or moderation into n8n’s direct provider path.
