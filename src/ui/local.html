      Computer requirements

      Windows, macOS, Linux, or WSL2. Windows uses Docker Desktop's desktop-linux engine and an owner-only NTFS ACL for Relmio credentials. macOS, Linux, and WSL2 use owner-only file permissions.

      Connection details and limits

      n8n with ChatGPT sign-in uses a local SIWC preview registration, separate from personal Codex credentials and Platform API billing. Verified identity alone cannot use the plan. You approve plan permission in ChatGPT and background n8n use separately. Relmio transfers one selected registration to an owned sidecar on the reviewed Docker network; n8n itself stays unchanged. The one-time Relmio client key is entered in n8n by you. Models come from that account's catalog, but a list does not prove a request will finish. This integration does not support image generation, audio, video, Files upload, or stored conversations. Old bridges need an explicit reviewed migration with a fresh sign-in.

      Grok for n8n uses official SuperGrok sign-in only. It adds a private Chat Completions companion. No provider token or API key is entered here.

      Codex App Server is an experimental JSON-RPC WebSocket for a trusted native app. It is not OpenAI /v1. Browsers cannot connect directly.

      Codex Chat Adapter is an experimental POST /chat endpoint for a trusted local backend. It is not /v1. Do not put it in browser code.

      n8n AI Assistant tools add a private Code Sandbox and optional SearXNG search. The sandbox runner is privileged and host-root equivalent. For production, use Daytona. Relmio does not edit or restart n8n.

      Local model for n8n publishes no host port. Other containers on its network can use the model API without a password. Relmio checks free memory and disk before download. CPU answers can be slow. There is no cloud fallback.

      Set up new n8n creates a separate stack. The public link requires Basic Auth. Existing n8n is not changed.

      Grok on this computer is experimental. Official SuperGrok sign-in stays in its runtime. Clients use a separate Relmio key, not a Platform API key.

        What Relmio will and will not do

        Relmio will

        • Build one Docker image for this connection.
        • Publish the selected port on 127.0.0.1 only.
        • Make a separate one-time local key.
        • Keep provider sign-in in a private Docker volume.

        Relmio will not

        • Publish the endpoint on your network or the internet.
        • Turn provider sign-in into an API key.
        • Change or restart n8n.
        • Reuse an existing server deployment.

        Step 3 of 4 · Install

        Install

        Install the reviewed connection only after checking its selected account and destination.

        High-trust local key

        Anyone with this key can control Codex in its container, act through your ChatGPT sign-in, and may recover that container's ChatGPT session. Treat it like your ChatGPT password. Give it only to a trusted local app.

        Private ChatGPT plan sidecar

        The selected registration transfers to an owned local sidecar. Approve n8n background use separately, then enter the one-time Relmio client key in n8n yourself. Relmio does not edit or restart n8n or publish port 10531. An uncertain installation requires owner inspection before use.

        Privileged testing companion

        Relmio starts only its Code Sandbox services and the SearXNG option you chose. The runner is privileged Docker-in-Docker and host-root equivalent. It will not change n8n. Copy the returned settings into n8n yourself. For production, use Daytona.

        Public link needs Basic Auth

        Create the Basic Auth username and password yourself. They do not come from ngrok, n8n, Relmio, Windows, or ChatGPT. Save them: Relmio does not show them again.
